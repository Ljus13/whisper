Phase 1: Database & Core Logic (งานหลังบ้านและกฎของระบบ)

โครงสร้างฐานข้อมูลแบบแบน: เชื่อมตารางการต่อสู้เข้ากับตาราง Profiles ของผู้เล่นโดยตรง การบวกลบค่า HP, Sanity, Spirituality จะพุ่งไปอัปเดตที่ตัวละครจริงทันที

ระบบ Log แบบ JSONB: บันทึกประวัติทุกอย่าง (การโจมตี, เลือดลด, ลิงก์โรลเพลย์, ประกาศจาก DM) ยัดลงคอลัมน์ JSONB เพื่อความยืดหยุ่นและโหลดไว

กฎการจำกัดพื้นที่: เขียน Logic ตรวจสอบระดับ Database/Server ว่า ผู้เล่น 1 คน สามารถอยู่ในห้องต่อสู้ (ที่สถานะยัง Active) ได้เพียง 1 ห้องเท่านั้น

Phase 2: Combat Lobby & Room Creation (ระบบเตรียมความพร้อมและสร้างห้อง)
หน้าจอสำหรับทีมงานในการตั้งโต๊ะก่อนเริ่มการต่อสู้

การสร้างห้องต่อสู้: ทีมงานกดสร้างห้อง ตั้งชื่อสถานการณ์ และเลือกรายชื่อผู้เล่นที่จะดึงเข้าฉากนี้ (เลือกจากฐานข้อมูล)

การสร้าง NPC ศัตรูแบบ On-the-fly: เนื่องจากศัตรูไม่มี Profile ถาวร ในหน้านี้จะมีฟอร์มง่ายๆ ให้ทีมงานพิมพ์ชื่อศัตรู และกรอกตัวเลขตั้งต้นของ HP, Sanity, Spirituality เพื่อเสกศัตรูเข้าห้องได้แบบด่วนๆ ทันที

การเริ่มฉาก: เมื่อผู้เล่นและศัตรูครบ กดปุ่ม "เริ่มฉาก" เพื่อล็อคห้อง (ห้ามคนเข้าเพิ่ม) และเริ่มนับเวลา

Phase 3: The "Fast & Ugly" Admin Dashboard (หน้าจอพระเจ้าสำหรับทีมงาน)
หน้าควบคุมหลักที่ตัดความสวยงามทิ้ง เน้นใช้แท็ก HTML Table ดิบๆ เพื่อความไวระดับเสี้ยววินาที

Layout ตาราง: แบ่งเป็นตาราง "ฝั่งผู้เล่น" (บน) และ "ฝั่งศัตรู" (ล่าง) แสดงแค่รูปกับชื่อ

เครื่องมือ Direct Edit: * หลอด HP, Sanity, Spirituality จะมีปุ่ม + / - หรือช่องกรอกตัวเลข กดปุ๊บคำนวณลง Database ทันที

Dropdown สำหรับยัด "สถานะผิดปกติ" ให้ตัวละคร (มีสองคอลั่ม ยัดสูงสุดได้ 2 สถานะ)

ระบบเทิร์นสไตล์ DM: มีปุ่ม "มอบเทิร์น" ท้ายชื่อตัวละคร แอดมินอยากให้ใครเล่นก็กดปุ่มนั้น คนอื่นจะถูกปรับเป็นสถานะ "รอ" อัตโนมัติ

ระบบประกาศิต: มีช่อง Textarea ด้านบนสุด พิมพ์ข้อความแล้วกด "📢 ประกาศ" ในหน้าผู้เล่นจะมีข้อความเด่น ๆ แจ้งอยู่กลางจอด้านบนสุดของเนื้อหาทันที

Phase 4: Player UI & Global Alert (หน้าจอคนดูและการแจ้งเตือน)
ฝั่งผู้เล่นที่เน้นความสวยงาม สไตล์ Cosmic Horror และทำงานแบบ Read-only ตอบสนองตามคำสั่งแอดมิน

Global Alert (ระบบดึงตัวผู้เล่น): หากผู้เล่นคนนั้นมีชื่ออยู่ในห้องต่อสู้ที่กำลัง Active แต่ดันเปิดไปหน้าอื่นของเว็บไซต์ (เช่น หน้าโปรไฟล์ หรือหน้าวิกิ) ระบบจะดึง UI แจ้งเตือนของระบบ Punishment มาใช้ โดยขึ้นแถบแดงเด่นๆ ว่า "⚠️ คุณกำลังอยู่ในการต่อสู้!" พร้อมปุ่มกดวาร์ปกลับมาที่ห้องต่อสู้

Reactive UI: แบ่งจอซ้าย-ขวา หรือ บน-ล่าง (มือถือ) โทนสีฟ้าและแดง เมื่อแอดมินมอบเทิร์นให้ กรอบตัวละครของคนนั้นจะเรืองแสง และปุ่ม "ส่งลิงก์โรลเพลย์" จะโผล่ขึ้นมา

Visual Status Effects: เมื่อโดนยัดสถานะผิดปกติ จะมี CSS โผล่ที่จอ โดยหากมีซ้อนกันมากกว่า 1 ให้ยึดคอลั่มแรกในหน้าแอดมินเป็นหลัก แสดงเอฟเฟคแค่อันเดียว
- มึนงง - แสงสีขาวเหลือง สลับกันกระพริบจากขอบจอ
- ถูกแช่แข็ง - สีฟ้า Gradient ไล่มาจากขอบจอ
- ถูกสาป - สีม่วง สลับแดง Gradient ไล่มาจากขอบจอ
- ถูกออร่าแห่งความตาย - สี Teal Gradient ไล่มาจากขอบจอ
- หลับใหล - จอมืดสนิท มี Overlay แจ้งข้อความสีม่วงแดง เรืองแสงว่า "คุณกำลังอยู่ในสภาะนอนหลับ"
- เผาไหม้ - สีแดงสลับส้ม Gradient ไล่มาจากขอบจอ
- แสงจ้า - สีขาวกระพริบ ไล่มาจากขอบจอ
- อัมพาต - จอมืดสนิท มี Overlay แจ้งข้อความสีทอง เรืองแสงว่า "ติดสถานะอัมพาต"
- ติดพิษ - สีเขียว Gradient ไล่มาจากขอบจอ
- คุ้มคลั่ง - สีแดงสลับฟ้า กระพริบ ไล่มาจากขอบจอ
- ตาบอด - จอมืดสนิท มี Overlay แจ้งข้อความแดง เรืองแสงว่า "ติดสถานะมองไม่เห็น"
- เลือดใหล - สีแดง Gradient ไล่มาจากขอบจอ
- หลงใหล - สีชมพู Gradient ไล่มาจากขอบจอ
- จมน้ำ - สีฟ้าสลับขาว Gradient ไล่มาจากขอบจอ

เงื่อนไข ติดสถานะต่อไปนี้ แม้ถึงเทิร์นตัวเอง ก็จะไม่สามารถกดปุ่มหรือใช้งาน ส่งลิงก์โรลเพลย์ได้ 
มึนงง, ถูกแช่แข็ง, อัมพาต, หลงใหล

มีแจ้งบนหน้าจอเสมอว่า กำลงัมีสถานะอะไรติดอยู่ และมีแจ้งในกล่องโปรไฟล์ในหน้าต่อสู้ด้วย

Screen-Takeover: หากทีมงานกดส่ง "ประกาศ" หน้าจอผู้เล่นจะถูก Overlay สีดำแดงคลุมทับ 100% บังคับให้อ่านและกด "รับทราบ" ถึงจะกลับมาดูการต่อสู้ต่อได้

Phase 5: Combat Logs & Feed (ระบบบันทึกประวัติ)

Unified Feed: ดึงข้อมูล JSONB มาแสดงเรียงกัน ทั้งประวัติการหักเลือด, การส่งลิงก์, และคำประกาศจาก DM

Performance Limit: ดึงมาแสดงผลครั้งละ 10 แถว (Limit 10) และมีปุ่ม Pagination ให้กดดูประวัติย้อนหลังได้ เพื่อไม่ให้หน้าจอรกจนเกินไป
